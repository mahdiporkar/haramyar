# ممیزی اولیهٔ استقرار — ۲۰۲۶-۱۰-۱۶

وضعیت: استقرار انجام نشده است؛ دامنه تأیید شد، اما سرور احراز هویت SSH با کلید موجود را نپذیرفت.

## پیگیری پس از پاسخ کاربر

- کاربر دامنهٔ `haramyar.com` را تأیید کرد و استفاده از نام کاربری اتصال قبلی Husbantech را خواست.
- در سابقهٔ اتصال همین سرور، نام کاربر `claude-deploy` و کلید `claude-deploy_si-871841_ed25519` پیدا شد.
- اجرای واقعی OpenSSH با مجوز خارج از sandbox، پورت `9011`، کلید مذکور، `IdentitiesOnly=yes` و بررسی سخت‌گیرانهٔ کلید میزبان انجام شد.
- دستور فقط‌خواندنی `whoami` به علت `Permission denied (publickey,password)` اجرا نشد. تأیید نشده است که حساب هنوز فعال است یا کلید در authorized_keys آن وجود دارد.
- نیاز بعدی: فعال‌بودن دسترسی حساب با کلید عمومی موجود یا معرفی اتصال معتبر جایگزین از مسیر امن. هیچ تغییری روی سرور انجام نشد.

## موارد تأییدشده

- سرور هدف طبق درخواست صریح کاربر: `141.11.45.119`.
- اتصال TCP به پورت `9011` موفق بود. این پورت در فایل محلی `known_hosts_si871841` نیز ثبت شده است؛ احراز هویت SSH آزمایش نشده است.
- درخواست مستقیم HTTP به IP روی پورت 80 پاسخ `200 OK` با سرآیند `Server: nginx` داد. این پاسخ سلامت HaramYar یا CapRover را اثبات نمی‌کند.
- مخزن محلی: `https://github.com/mahdiporkar/haramyar.git`، شاخهٔ `main`، کامیت `19c72011f2cf9ebc9d75ffe58c161258753aff25`.
- تغییرات ثبت‌نشده از قبل وجود داشتند و حفظ شدند.
- سرویس‌های موجود در سورس: Booking (پورت پیش‌فرض 8090)، Martyrs (8091)، shell-service (8092) و افزونهٔ موبایل Keycloak.
- مسیرهای frontend معرفی‌شده در package.json، از جمله `apps/public-web`، `apps/haramyar-shell` و frontend دو ماژول، در زمان بررسی موجود نبودند. Dockerfile، captain-definition و workflow استقرار نیز یافت نشدند.

## محدودیت‌های بررسی

- نام کاربر SSH در تنظیمات بررسی‌شده مشخص نبود؛ از کاربر درخواست شد. کلید خصوصی خوانده یا منتشر نشد.
- دامنه‌های `haramyar.com` و `harmyar.com` در ورودی متناقض‌اند؛ مطابق دستور پیوست باید دامنه و اختیار مدیریت آن تأیید شود.
- DNS محلی برای اولی خطای `REFUSED` و برای دومی `NXDOMAIN` برگرداند؛ این نتایج برای نتیجه‌گیری قطعی دربارهٔ DNS عمومی کافی نیستند.
- Git با پروکسی محیطی به `127.0.0.1:9` متصل نشد. تلاش مستقیم با OpenSSL به مرحلهٔ درخواست اعتبارنامه رسید ولی دریافت اعتبارنامه در این محیط شکست خورد؛ وضعیت remote و جدیدترین نسخه تأیید نشد.
- نسخه‌های Ubuntu/Docker/CapRover، منابع، سرویس‌ها، volumeها، پشتیبان‌ها، TLS و تنظیمات registry هنوز بررسی نشده‌اند؛ نیازمند ورود مجاز به سرور هستند.
- هیچ تغییر سروری، DNS، TLS، دیتابیس یا GitHub انجام نشد. هیچ تست production یا migration اجرا نشد.

## ادامهٔ اجرا

پس از دریافت نام کاربر و تأیید روش SSH، ابتدا ممیزی فقط‌خواندنی سرور انجام شود. سپس نسخهٔ کامل قابل ساخت پروژه تعیین، ظرفیت سنجیده و توپولوژی نهایی با سرویس‌های مستقل، دادهٔ پایدار و شبکهٔ داخلی آماده شود. تنظیم hostname و صدور TLS منوط به تأیید دامنه است. پاسخ HTTP فعلی نباید به‌عنوان موفقیت استقرار گزارش شود.
